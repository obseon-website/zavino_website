# Cloudflare Next.js Recommendations

> **Universal playbook for shipping any new Next.js 16 (App Router) site to Cloudflare Workers via OpenNext (`@opennextjs/cloudflare`).**
> This is the exact method used to host production on a standard Cloudflare account (Workers + D1 + Wrangler) — packaged so any AI or engineer can reuse it for a brand-new project without rediscovering the pitfalls.
>
> **Proven in production:** Next.js 16.3.1 · React 19 · `@opennextjs/cloudflare` 1.20.2 · Wrangler 4.124 · Drizzle ORM + D1 (SQLite) on `everrisepress.com`. Provenance ≠ dependency — replace all placeholders with your project values.
>
> **How to use this doc:** Feed it verbatim to any AI that will scaffold, migrate, or deploy a Next.js app to Cloudflare. The AI must treat violations of §0 as build failures.
>
> **Legend:** `<PLACEHOLDER>` = replace for your project. `YOUR_WORKER_NAME`, `YOUR_D1_NAME`, `YOUR_DOMAIN` (e.g. `example.com`), `YOUR_SITE_URL` (e.g. `https://example.com`).

> **Upstream truth (2026):** Always re-validate OpenNext docs at https://opennext.js.org/cloudflare, Wrangler schema at `node_modules/wrangler/config-schema.json`, and Workers/D1 limits at https://developers.cloudflare.com/workers/platform/limits/. This doc pins known-good versions but upstreams move.

## 0. TL;DR — The 10 non-negotiables for every new project

1. **Host on Cloudflare *Workers*, not Pages.** OpenNext adapter contract = `wrangler.jsonc` with `main: ".open-next/worker.js"` and `assets.directory: ".open-next/assets"`. Pages is a separate product with different caching/bindings — don't mix them.
2. **Never use `next build` as the Cloudflare build command.** The Cloudflare build step must be `npx opennextjs-cloudflare build` (via `npm run preview` / `deploy`). Keep `package.json:scripts.build` as `next build` only for local typechecks.
3. **Every D1/database-backed page/route is `force-dynamic` + `runtime = "nodejs"` where it touches the DB.** D1 does not exist at build time — any `revalidate`/`generateStaticParams` that queries the DB will crash with `no such table`.
4. **Read D1 only via `getCloudflareContext({ async: true })`.** Never `process.env.DATABASE_URL`, never hardcode a connection string. See §6.
5. **Track Worker compressed size like a budget.** Hard limit **~3072 KiB gzip** — one 2 MB inlined SVG or a `next/og` dynamic OG route can kill the deploy.
6. **`wrangler.jsonc` must have `compatibility_date` = today and `compatibility_flags` = `["nodejs_compat","global_fetch_strictly_public"]`.**
7. **If R2 is not enabled on the account, disable incremental cache.** `open-next.config.ts` → `defineCloudflareConfig({})` (no-op cache). Don't add `r2_buckets` bindings until R2 is confirmed active.
8. **Env = three layers, never mixed.** `.env.local` (Next dev) vs `.dev.vars` (Wrangler local) vs `wrangler.jsonc:vars` (public) vs `wrangler secret put` (secrets). Never put secrets in `wrangler.jsonc`.
9. **Run `npm run cf-typegen` after every binding change.** Keep `cloudflare-env.d.ts` committed and in `tsconfig.json:include`.
10. **Prefer `app/(group)/layout.tsx` guards over `middleware.ts` for cookie-based auth** on Workers — `HttpOnly`/`Secure` cookie edge quirks in middleware cause redirect loops.

## 1. Cloudflare mental model: Workers ≠ Pages

|  | Cloudflare Pages (legacy Next) | **Cloudflare Workers + OpenNext (this guide)** |
|---|---|---|
| Build output | `out/` or `.vercel/` | `.open-next/worker.js` + `.open-next/assets/` |
| Config entry | `pages_build_output_dir` | `wrangler.jsonc:main` + `assets.directory` |
| ISR / Cache | Pages Functions | Cloudflare Cache API + `open-next.config.ts` |
| DB access | Not trivial | `getCloudflareContext` / D1/KV/R2 bindings |
| Image optimization | Pages Images | `images.binding: "IMAGES"` |

Pick Workers + OpenNext for any new project that needs D1/KV/R2, auth, or API routes. The `main` file `.open-next/worker.js` only exists after `opennextjs-cloudflare build`.

## 3. Critical config files (universal templates)

### 3.1 `wrangler.jsonc` — deploy contract

This is the template to copy for every new project. Replace every `YOUR_` value:

```jsonc
{
  "$schema": "node_modules/wrangler/config-schema.json",
  "main": ".open-next/worker.js",          // ← NOT src/index.ts — generated by OpenNext
  "name": "YOUR_WORKER_NAME",              // e.g. "my-app" — must match services[].service
  "account_id": "YOUR_CLOUDFLARE_ACCOUNT_ID",
  "compatibility_date": "2026-09-19",      // ALWAYS set to today for new projects
  "compatibility_flags": [
    "nodejs_compat",                       // required for Next 16 + jose + Web Crypto
    "global_fetch_strictly_public"
  ],
  "vars": {                                // PUBLIC only — inlined at build, visible to client
    "NEXT_PUBLIC_SITE_URL": "https://YOUR_DOMAIN",
    "NEXT_PUBLIC_TURNSTILE_SITE_KEY": "YOUR_TURNSTILE_SITE_KEY"
    // add other NEXT_PUBLIC_* here — never secrets
  },
  "assets": {
    "directory": ".open-next/assets",     // OpenNext static asset output
    "binding": "ASSETS"                   // Fetcher available as env.ASSETS
  },
  "services": [
    { "binding": "WORKER_SELF_REFERENCE", "service": "YOUR_WORKER_NAME" }
    // required for Cache API / ISR revalidation via service binding
    // value MUST equal `name` above — see https://opennext.js.org/cloudflare/caching
  ],
  "images": {
    "binding": "IMAGES"                  // enables next/image via Cloudflare Images
    // see https://opennext.js.org/cloudflare/howtos/image
  },
  "d1_databases": [
    {
      "binding": "DB",                    // access as env.DB in code
      "database_name": "YOUR_D1_NAME",    // e.g. "my-app-db"
      "database_id": "YOUR_D1_DATABASE_ID", // UUID from `wrangler d1 create`
      "migrations_dir": "./migrations"
    }
  ]
}
```

**Rules for every project:**
- `vars` = public env only (`NEXT_PUBLIC_*`, feature flags). Secrets (`TURNSTILE_SECRET_KEY`, `JWT_SECRET`, `SESSION_SECRET`, API tokens) → `npx wrangler secret put <NAME>` or Dashboard → Workers → Settings → Secrets. Never in `wrangler.jsonc`, never committed.
- If you add, rename, or remove any binding, immediately run `npm run cf-typegen` (§5).
- `account_id` can be omitted if you use `wrangler login` + `wrangler.jsonc` without it, but pinning it avoids deploying to the wrong account when you manage multiple Cloudflare accounts.

### 3.2 `open-next.config.ts` — caching decision

**Default for most new projects (no R2 / fully dynamic):**

```ts
import { defineCloudflareConfig } from "@opennextjs/cloudflare";

// R2 incremental cache is disabled by default.
// With no incrementalCache override, OpenNext uses a no-op cache.
// This is correct when all DB-backed pages are `force-dynamic`.
// To enable ISR, see https://opennext.js.org/cloudflare/caching
export default defineCloudflareConfig({});
```

**Only when R2 is confirmed enabled on the account and you want ISR:**

```ts
import { defineCloudflareConfig } from "@opennextjs/cloudflare";
import r2IncrementalCache from "@opennextjs/cloudflare/overrides/incrementalCache/r2IncrementalCache";

export default defineCloudflareConfig({
  incrementalCache: r2IncrementalCache({ bucket: "YOUR_R2_BUCKET_NAME" }),
});
```

Then also add to `wrangler.jsonc`:
```jsonc
"r2_buckets": [{ "binding": "NEXT_INC_CACHE_R2_BUCKET", "bucket_name": "YOUR_R2_BUCKET_NAME" }]
```
If you add the binding but R2 is disabled on the account, deploy hard-fails. The safe default is the no-op config above.

Keep this file even when empty — OpenNext reads it at build.

### 3.3 `next.config.ts` — Workers-aware Next config

```ts
import type { NextConfig } from "next";
import { initOpenNextCloudflareForDev } from "@opennextjs/cloudflare";

initOpenNextCloudflareForDev(); // makes `next dev` able to resolve getCloudflareContext

const nextConfig: NextConfig = {
  reactStrictMode: true,
};

export default nextConfig;
```

- **Do not** add `output: "export"` or `output: "standalone"` — both break Workers.
- `initOpenNextCloudflareForDev()` only runs in dev; it doesn't affect the Worker.

### 3.4 `drizzle.config.ts` — D1 dialect

```ts
import { defineConfig } from "drizzle-kit";

export default defineConfig({
  schema: "./src/lib/db/schema.ts",
  out: "./migrations",
  dialect: "sqlite",
  driver: "d1-http",
});
```

- `dialect: "sqlite"` + `driver: "d1-http"` is the only correct combo for Cloudflare D1.
- Works for any SQLite schema — not coupled to a specific table set.

### 3.5 `tsconfig.json` + `eslint.config.mjs` — don't ignore the generated types

```jsonc
// tsconfig.json — include the generated types
{
  "compilerOptions": { /* ... */ },
  "include": [
    "next-env.d.ts",
    "cloudflare-env.d.ts",   // ← generated by `wrangler types`
    "**/*.ts",
    "**/*.tsx",
    ".next/types/**/*.ts"
  ]
}
```

```js
// eslint.config.mjs — ignore build outputs, not the env file
import { defineConfig, globalIgnores } from "eslint/config";
import nextVitals from "eslint-config-next/core-web-vitals";
import nextTs from "eslint-config-next/typescript";

export default defineConfig([
  ...nextVitals,
  ...nextTs,
  globalIgnores([".next/**", ".open-next/**", "out/**", "build/**", "next-env.d.ts"]),
  // do NOT ignore cloudflare-env.d.ts — it's committed and should be linted for drift
]);
```

- Add `cloudflare-env.d.ts` to `tsconfig.json:include` and **commit it** (remove it from `.gitignore` if present). This is how CI and other AIs see your bindings.

### 3.6 `public/_headers` — static asset caching

```
# https://developers.cloudflare.com/workers/static-assets/headers
# https://opennext.js.org/cloudflare/caching#static-assets-caching
/_next/static/*
  Cache-Control: public,max-age=31536000,immutable
```

Without this, `_next/static/*` chunks won't get long-lived edge caching.

## 4. Environment variables — the three-layer model

Every new project has three layers. Confusing them is the #1 source of "works locally, fails on Workers":

| Layer | File / place | When it's used | Example | Commit? |
|---|---|---|---|---|
| **Next dev** (`next dev`) | `.env.local` (gitignored) | `process.env.*` in Server/Client | `NEXT_PUBLIC_SITE_URL`, local `TURNSTILE_SECRET_KEY` | ❌ |
| **Workers local preview** (`wrangler dev` via OpenNext) | `.dev.vars` (gitignored) | `getCloudflareContext().env.*` | `TURNSTILE_SECRET_KEY`, `JWT_SECRET`, `API_TOKEN` | ❌ |
| **Workers deployed — public** | `wrangler.jsonc:vars` | `env.*` on the worker | `NEXT_PUBLIC_SITE_URL`, `NEXT_PUBLIC_GA_ID` | ✅ |
| **Workers deployed — secret** | `wrangler secret put` / Dashboard Secrets | `env.*` on the worker (encrypted) | `TURNSTILE_SECRET_KEY`, `JWT_SECRET`, `META_CAPI_TOKEN` | ❌ (in CF) |

### 4.1 Universal pattern (use for every project)

Create a single source of truth for the canonical URL and client env:

```ts
// src/lib/env.ts
export const env = {
  NEXT_PUBLIC_SITE_URL: "https://YOUR_DOMAIN",
  // add other NEXT_PUBLIC_* here — keep in sync with wrangler.jsonc:vars
};
```

```ts
// src/lib/seo/ids.ts (or src/lib/site.ts) — canonical SITE_URL export
import { env } from "@/lib/env";

export const SITE_URL = (
  process.env.NEXT_PUBLIC_SITE_URL || env.NEXT_PUBLIC_SITE_URL
).replace(/\/+$/, "");
```

In every server route, read secrets with dual fallback so both `next dev` and `wrangler dev` work:

```ts
const { env } = await getCloudflareContext({ async: true });
const secret = env.TURNSTILE_SECRET_KEY || process.env.TURNSTILE_SECRET_KEY;
const jwtSecret = new TextEncoder().encode(
  env.JWT_SECRET || process.env.JWT_SECRET || "fallback-only-for-dev"
);
```

Never hardcode `https://YOUR_DOMAIN` in app code — always route through `SITE_URL`.

### 4.2 Checklist before first deploy of any new project

```bash
npx wrangler secret put TURNSTILE_SECRET_KEY
npx wrangler secret put JWT_SECRET
# or any other secret your app needs
# create .dev.vars locally for `npm run preview` (same keys, no NEXT_PUBLIC_ duplication needed)
cat > .dev.vars <<'EOF'
TURNSTILE_SECRET_KEY=...
JWT_SECRET=...
EOF
```

## 5. Local dev / preview / deploy workflow (identical for every project)

### `package.json` scripts to use for all new projects

```json
{
  "scripts": {
    "build": "next build",
    "build:worker": "opennextjs-cloudflare build",
    "dev": "next dev",
    "preview": "opennextjs-cloudflare build && opennextjs-cloudflare preview",
    "deploy": "opennextjs-cloudflare build && opennextjs-cloudflare deploy",
    "upload": "opennextjs-cloudflare build && opennextjs-cloudflare upload",
    "cf-typegen": "wrangler types --env-interface CloudflareEnv cloudflare-env.d.ts",
    "db:generate": "drizzle-kit generate",
    "db:migrate:local": "wrangler d1 migrations apply YOUR_D1_NAME --local",
    "db:migrate:remote": "wrangler d1 migrations apply YOUR_D1_NAME --remote",
    "db:studio": "drizzle-kit studio",
    "db:seed": "wrangler d1 execute YOUR_D1_NAME --file ./src/lib/db/seed.sql",
    "lint": "eslint",
    "check:size": "opennextjs-cloudflare build && wrangler deploy --dry-run"
  }
}
```

| Command | What it does | When to use |
|---|---|---|
| `npm run dev` | plain `next dev` via `initOpenNextCloudflareForDev()` | fast iteration |
| `npm run preview` | `opennextjs-cloudflare build` → `.open-next/` → `wrangler dev` local Worker | test D1/bindings/`next/image` locally before deploy |
| `npm run deploy` | build + `wrangler deploy` | ship to `*.workers.dev` + custom domain |
| `npm run build` | alone is **not** Cloudflare-deployable | only for typecheck/CI; never as CF build command |
| `npm run cf-typegen` | regenerates `cloudflare-env.d.ts` from `wrangler.jsonc` | after any binding change |
| `npm run check:size` | build + dry-run → prints compressed Worker size | before every deploy — see §7 |

### What the Cloudflare dashboard Build command must be

- **If you use Workers Git integration (recommended for all new projects):** Don't use Cloudflare *Pages*. Connect the repo as a **Worker**: Cloudflare Dashboard → Workers & Pages → Create Worker → Import from Git. Set **Build command** to `npx opennextjs-cloudflare build`. Leave deploy to Wrangler (`npx opennextjs-cloudflare deploy`). Do **not** set `next build`.
- **If you insist on Pages auto-build:** Override Build command to `npx opennextjs-cloudflare build` and Output directory to `.open-next/assets` — but you'll lose D1/KV/R2 bindings. Migrate to Workers instead.
- **The classic mistake:** Leaving the dashboard on `npm run build` (plain Next) then wondering why D1 queries crash with `no such table` during build. The fix is code-level (`dynamic = "force-dynamic"` on every DB-backed page, §6) *and* the dashboard build command above — both.

## 6. D1 + Drizzle — the one pattern that works for any schema

This pattern is schema-agnostic — it works whether your app has 1 table or 30.

### 6.1 Schema

Use `drizzle-orm/sqlite-core` (`sqliteTable`, `text(..., { mode: "json" })` for JSON, `integer(..., { mode: "boolean" })` for booleans, `real` for prices). Any valid Drizzle SQLite schema qualifies — no coupling to the EverRise tables.

### 6.2 Migrations

```bash
npm run db:generate           # drizzle-kit generate → migrations/####_name.sql
npm run db:migrate:local      # wrangler d1 migrations apply YOUR_D1_NAME --local
npm run db:migrate:remote     # wrangler d1 migrations apply YOUR_D1_NAME --remote
npx wrangler d1 migrations list YOUR_D1_NAME --remote  # audit
```

- `migrations/meta/_journal.json` is the source of truth for order. Don't hand-edit a `*.sql` after it has been applied `--remote`.
- Seed via SQL files for Wrangler: `npx wrangler d1 execute YOUR_D1_NAME --file ./src/lib/db/seed.sql` (TS seeds don't run via `wrangler d1 execute`).

### 6.3 Reading the DB at request time (the contract for every new project)

**Every D1-backed file must start with:**

```ts
export const dynamic = "force-dynamic";  // disable static generation — D1 not at build time
export const runtime = "nodejs";         // when you use D1, Web Crypto, or `jose`
```

**Single DB accessor to use everywhere:**

```ts
// src/lib/db/client.ts
import { getCloudflareContext } from "@opennextjs/cloudflare";
import { getDb } from "./index";

export async function getDatabase() {
  const { env } = await getCloudflareContext({ async: true });
  return getDb(env.DB);
}
```

```ts
// src/lib/db/index.ts
import { drizzle } from "drizzle-orm/d1";
import * as schema from "./schema";

export function getDb(d1: D1Database) {
  return drizzle(d1, { schema });
}
```

- Always `await getCloudflareContext({ async: true })` — the sync form is deprecated and misses `ctx`.
- In API routes / edge routes (`app/api/**/route.ts`, `app/refer/[code]/route.ts`, etc.) destructure `{ env, ctx }` and use `ctx.waitUntil()` for fire-and-forget work (analytics, logging) so it doesn't block the response.

### 6.4 Performance pattern to apply from day one

`force-dynamic` means every request hits D1 (typical warm cost 100–160 ms). For every new project, plan:

- **Parallelize sequential `db.select()` calls** — don't `await` 2–3 queries serially; use `Promise.all` or `D1 batch()`.
- **HTML edge caching later** — Cloudflare Cache API + `stale-while-revalidate` for mostly-static marketing pages, invalidated when admin edits touch DB rows. Leave `/preview`, `/admin`, and any authenticated routes uncached.
- Don't add R2 ISR until R2 is proven enabled on the target account.

## 7. Worker bundle size — the 3 MiB wall (applies to every project)

**Limit:** Cloudflare Workers compressed script size **~3072 KiB gzip** (printed by `wrangler deploy --dry-run`). Exceeding it fails the deploy with `Script too large` — no partial deploy, no warning in `next build`.

### 7.1 Real-world examples from production (what to avoid in your new project)

| Before | After | Cause | Universal lesson |
|---|---|---|---|
| 3068 KiB gzip | 1245 KiB | A 1.97 MB SVG that contained an embedded raster PNG was imported from `src/app/` and inlined into the Worker JS | Never import large assets from `src/` — keep raster images in `public/` and reference by URL |
| 2985 / 3072 KiB | ~2100 KiB | Dynamic OG image route (`app/api/og/route.tsx` via `next/og` / Satori) pulled in wasm + fonts | Prefer **static OG images** (`public/images/og/*.png` pre-generated) over `next/og` on Workers — Satori costs ~800 KiB |

### 7.2 Audit before every deploy (add to your checklist for all projects)

```bash
npx opennextjs-cloudflare build
npx wrangler deploy --dry-run  # prints compressed size
# if > 2800 KiB → investigate now, not after merge
```

### 7.3 Rules for every new project

- **Never inline large assets.** An SVG that embeds base64 PNG/JPG *is* a large JS string in the bundle.
- **Prefer static OG images** (1200×630 PNGs in `public/images/og/`) over `next/og`. Dynamic OG is elegant but expensive on Workers.
- **Watch heavy deps:** `recharts`, `framer-motion`, `gsap`, `lenis`, `schema-dts` and similar all add size. Lazy-load charts/modals; keep `app/(admin)` routes code-split via route groups.
- **Use `webp`/`avif`** for covers/carousel/hero images (often 5 MB JPG → 100 KiB webp).
- **Audit after every `npm install`.** One dependency can push you over.

## 8. Images, assets, and caching — universal setup

- **`IMAGES` binding** (`wrangler.jsonc:images` → `IMAGES`) + `next/image` works transparently via the OpenNext image handler. Still set `priority` on the LCP/hero image and accurate `sizes` on every `<Image>`.
- **`ASSETS` fetcher** serves `.open-next/assets`. Don't write to it manually.
- **`public/_headers`** controls static asset caching — keep `_next/static/*` as `immutable` (see §3.6).
- **R2 for uploads is opt-in** — only add `r2_buckets` + upload routes after confirming R2 is enabled on the target Cloudflare account (Dashboard → Products → R2). The Cloudflare Images binding already handles `next/image` without R2.

## 9. Auth, bot protection, and referral — Worker-safe patterns (adapt to your project)

These are proven patterns for any new project that needs auth, Turnstile, or attribution — rename the cookies/tables to your domain.

### 9.1 Auth (if your new project has an admin or user area)

- **Hash:** Use **PBKDF2-SHA256 via Web Crypto** (`crypto.subtle.deriveBits`), not `bcrypt` — Node-only `bcrypt` crashes on Workers. 100k iterations is a good default.
- **Session:** `jose` `SignJWT` → `HttpOnly` cookie (e.g. `admin_session`, 7 days) with `Secure` in prod, `SameSite=Lax`.
- **Guard placement:** Put the auth guard in **`app/(admin)/admin/(panel)/layout.tsx`** (server layout that `redirect("/admin/login")`), not in `middleware.ts`. `middleware.ts` + `HttpOnly`/`Secure` cookies on Workers caused a redirect loop in production because the cookie wasn't readable in the middleware context.

### 9.2 Turnstile (if you collect emails or have forms)

- Client: `@marsidev/react-turnstile`.
- Server: `verifyTurnstileToken(token, secret)` → `fetch("https://challenges.cloudflare.com/turnstile/v0/siteverify", ...)` with `application/x-www-form-urlencoded`. Read the secret with dual fallback:

```ts
const { env } = await getCloudflareContext({ async: true });
const secret = env.TURNSTILE_SECRET_KEY || process.env.TURNSTILE_SECRET_KEY;
```

### 9.3 Referral / attribution cookie (if your new project has partners/UTM)

- Example: cookie name `YOUR_REF_COOKIE` (production used `everise_ref`), 30 days, `HttpOnly`, `SameSite=Lax`, `Secure` in prod.
- Edge route pattern: `app/refer/[code]/route.ts` → normalize slug → D1 lookup (check `isActive`) → insert click row (hash `CF-Connecting-IP` with `SHA-256` for privacy, log `user-agent`/`referer`/`CF-IPCountry`) → `ctx.waitUntil(analyticsCapture)` → `302` redirect to canonical page with `utm_source`/`utm_medium`/`utm_campaign` + optional `distinctId` for analytics ID unification.
- Lead/API routes read the cookie and attach `partnerId`/`sourceUtm` to the created row; if a prior anonymous lead later converts via referral, backfill the attribution.
- Unknown/inactive codes should `302` to `/` with no click logged.

### 9.4 Analytics — `ctx.waitUntil` is mandatory

```ts
const { env, ctx } = await getCloudflareContext({ async: true });
const capture = captureServerEvent(distinctId, "lead_generated", { ... });
if (ctx && typeof ctx.waitUntil === "function") ctx.waitUntil(capture);
// never `await` analytics inline — it will delay the 302/JSON response
```

This applies to PostHog, GA4, Meta CAPI, or any server-side event. Use `waitUntil` so analytics failures never break the user-visible response.

## 10. SEO layer that survives Cloudflare (optional, but works for any project)

The pattern below is schema-agnostic and works whether you have one content type or ten. It shipped registry-driven on `@jdevalk/seo-graph-core 0.7.0` (pinned exact):

- One file per page type (`home | book | author | article | ...`) drives: JSON-LD graph + Next `Metadata` (title/canonical/OG/Twitter) + breadcrumbs + sitemap entries + `llms.txt` sections + corpus endpoints (`/schema.json`, `/schemamap.xml`, `/.well-known/api-catalog`).
- **Canonical URL single source:** `SITE_URL` from `src/lib/seo/ids.ts` = `process.env.NEXT_PUBLIC_SITE_URL || env.NEXT_PUBLIC_SITE_URL`. Never hardcode `https://YOUR_DOMAIN` in SEO code.
- **Static OG images:** `public/images/og/*.png` (1200×630) referenced in metadata — see §7.3.
- `sitemap.ts` / `robots.ts` / `llms.txt/route.ts` are all `force-dynamic` and query D1 live (new rows auto-appear, no rebuild).

For a new project without SEO needs, you can skip this — but keep the `SITE_URL` singleton and static OG pattern regardless.

## 11. Cloudflare Dashboard deployment checklist (use for every new project)

1. **Wrangler auth:** `npx wrangler login` (use the Cloudflare account that owns `YOUR_DOMAIN`).
2. **D1:** `npx wrangler d1 migrations apply YOUR_D1_NAME --remote` and seed if needed. Confirm with `npx wrangler d1 migrations list YOUR_D1_NAME --remote`.
3. **Secrets:**
   ```bash
   npx wrangler secret put TURNSTILE_SECRET_KEY
   npx wrangler secret put JWT_SECRET
   # add any other secrets your app needs (e.g. META_CAPI_TOKEN, POSTHOG_API_KEY)
   ```
4. **Worker → Settings → Variables (public):**
   - `NEXT_PUBLIC_SITE_URL=https://YOUR_DOMAIN` (canonical — must match your actual domain)
   - Any other `NEXT_PUBLIC_*` your app reads (PostHog key/host, GA ID, etc.)
   - Feature vars like `REFERRAL_DEFAULT_SLUG` if applicable (empty = sensible fallback)
5. **Triggers → Custom Domain:** add `YOUR_DOMAIN` (DNS must be on Cloudflare — orange-cloud the `A`/`CNAME` or let Cloudflare manage DNS).
6. **Build integration:** If using Git → Worker integration, set **Build command** to `npx opennextjs-cloudflare build` and deploy via `npx opennextjs-cloudflare deploy`. Do **not** use Pages auto-build with `next build`.
7. **Verify live:** `https://YOUR_DOMAIN/sitemap.xml`, `/robots.txt`, `/llms.txt`, `/schema.json` (if SEO enabled), and a DB-backed page all return 200.

## 12. Troubleshooting cookbook — 10 gotchas (all transferable to new projects)

| # | Symptom | Root cause | Fix (works for any new project) |
|---|---|---|---|
| 1 | `no such table: <name>` during build | Page/route used `revalidate` + `generateStaticParams` that queried D1 at build time | Change every D1-backed page/route to `export const dynamic = "force-dynamic"` |
| 2 | `Script too large (3068 KiB / 3072 KiB)` | Large asset (e.g. 2 MB SVG with embedded PNG) imported from `src/` and inlined | Move raster assets to `public/` and reference by URL; archive large inlined files |
| 3 | `Script too large 2985/3072` after adding OG | `next/og` (Satori wasm + fonts) exceeds budget | Delete the dynamic `app/api/og/route.tsx`; ship static `public/images/og/*.png` |
| 4 | `R2 bucket not found` / `NEXT_INC_CACHE_R2_BUCKET` error | `wrangler.jsonc` binds R2 but R2 is disabled on the account | Remove `r2_buckets` + binding from `wrangler.jsonc`/`cloudflare-env.d.ts`; set `open-next.config.ts` to `defineCloudflareConfig({})` |
| 5 | Admin login infinite redirect | `middleware.ts` auth guard wrapped the login page and couldn't read `HttpOnly` cookie | Move guard to `app/(group)/(panel)/layout.tsx` server layout with `redirect("/admin/login")` |
| 6 | `TURNSTILE_SECRET_KEY not configured` on preview | `.dev.vars` missing secret, code only read `process.env` | Read `env.SECRET || process.env.SECRET` after `getCloudflareContext({ async: true })` |
| 7 | `cloudflare-env.d.ts` stale / `Property 'DB' does not exist` | Added/removed a binding but didn't regenerate types | Run `npm run cf-typegen`; confirm `tsconfig.json:include` has `cloudflare-env.d.ts` |
| 8 | `500` on Workers but works on `next dev` | Inside Worker code used `process.env.SECRET`; Workers expose secrets on `env`, not `process.env` | Always `const { env } = await getCloudflareContext({ async: true })` + dual fallback (§4.1) |
| 9 | PWA manifest icons 404 | `src/app/manifest.json` referenced `public/` files with wrong path (e.g. `/src/app/icon.png/...`) | Reference as `/web-app-manifest-192x192.png` (files live in `public/`) |
| 10 | Slow pages (every request hits D1) | `force-dynamic` + sequential `await db.select()` calls | Batch with `Promise.all` / `D1.batch()`; later add Cache API HTML edge caching with DB-triggered invalidation |

## 14. DON'T list (for AIs and humans — every new project)

- **DON'T** set `output: "export"` in `next.config.ts` (breaks Workers).
- **DON'T** put secrets in `wrangler.jsonc:vars` or commit `.dev.vars` / `.env.local`.
- **DON'T** use `export const revalidate` + `generateStaticParams` on D1 pages (no D1 at build).
- **DON'T** import a multi-MB SVG/PNG from `src/` — keep it in `public/` and use URL.
- **DON'T** add `next/og` dynamic OG unless you can budget ~800 KiB bundle.
- **DON'T** use `@opennextjs/cloudflare` as `^` — pin the exact version (adapter breaks across minors). Known-good: `1.20.2`.
- **DON'T** add `R2_BUCKET` / `NEXT_INC_CACHE_R2_BUCKET` bindings until R2 is proven enabled on the target Cloudflare account (Dashboard → Products → R2).
- **DON'T** rely on `middleware.ts` for `HttpOnly` cookie auth without testing on Workers edge; prefer `app/(group)/layout.tsx` guards for admin/auth.
- **DON'T** forget `compatibility_flags: ["nodejs_compat"]` — Node 19 / `jose` / `crypto.subtle` will crash without it.
- **DON'T** gitignore `cloudflare-env.d.ts` — commit it so CI and follow-on AIs see the bindings.

## Appendix B — Version drift guard (check before each new project)

Don't trust baked knowledge — re-validate:

- OpenNext Cloudflare docs: https://opennext.js.org/cloudflare
- Wrangler config schema: `node_modules/wrangler/config-schema.json` or https://developers.cloudflare.com/workers/wrangler/configuration/
- `@opennextjs/cloudflare` peers: `next >=15.5.21 <16 || >=16.2.11`, `wrangler >=4.86.0`
- D1 limits: https://developers.cloudflare.com/d1/
- Workers limits (compressed size, CPU, subrequests): https://developers.cloudflare.com/workers/platform/limits/

Run `npx wrangler types` and `npx opennextjs-cloudflare build && npx wrangler deploy --dry-run` early and often — size and binding errors surface there, not in `next build`.
